Four Interlocking AI Systems That Transformed a Customer Support Operation

A single builder designed and deployed a suite of four AI-powered systems that collectively transformed how a high-growth vertical SaaS company (~150 employees, thousands of customers) handles customer support. The systems work together to automatically enrich, triage, classify, route, reply to, escalate, and capture praise from every inbound support conversation.

Four systems. Zero manual triage. Every conversation enriched, classified, and routed before an agent touches it.

The Problem

The support team was operating with essentially no automation. Every conversation arrived in the same undifferentiated queue, and agents had to manually piece together context before they could even begin helping.

Zero automatic enrichment. Agents saw the customer's message and nothing else. Every conversation started with 2–5 minutes of manual context-gathering — looking up account details, checking subscription status, reviewing history.

No systematic triage. Every conversation landed in the same queue. Product feedback sat next to urgent bugs. Testimonials mixed with billing questions. Nothing was pre-sorted.

Repetitive reply drafting. Agents wrote the same patterns over and over — similar greetings, similar troubleshooting steps, similar closings. Skilled writing time wasted on routine structure.

Unstructured engineering escalations. When a support agent needed engineering help, they manually created a ticket. No standardized format. No cross-linking between the support conversation and the engineering ticket. Context was lost in translation.

Customer praise disappeared. When a customer said something wonderful, the agent read it, maybe shared it in Slack — and it was forgotten. No systematic capture. No way to use testimonials for marketing or morale.

The Solution: Four Interlocking AI Systems

System 1: AI Support System

Automatic Enrichment + Two-Layer AI Triage

Every inbound conversation passes through a six-step pipeline that transforms a raw message into a fully enriched, classified, and routed record — before any agent sees it.

Step 1 — Message Normalization + Enrichment: HTML stripped to plain text. Session ID extracted. Customer profile loaded with account details, subscription status, and history.

Step 2 — Rule-Based Tagging (Before AI): Fast, deterministic checks run first. Support inquiry detection, feedback identification, enterprise account flagging, specialized support routing. Rules are cheap and instant — they handle the obvious cases before burning an AI call.

Step 3 — Gating Classifier (Fast AI): A single LLM call returns exactly one token: worse, nomad, testimonial, or not relevant. This is the gate. It costs almost nothing and runs in milliseconds.

Two-layer classification saves cost while ensuring nothing is missed. The fast gate handles 100% of messages for pennies. Only messages that need detailed analysis proceed to the second, more expensive pass.

Step 4 — Feedback Tracker Classifier (Detailed AI): For messages that pass the gate, a second LLM call loads the full category registry from Notion and returns structured JSON: category, sentiment, and Slack thread destination.

Step 5 — Routing Matrix: Each classification maps to a specific destination:

  • Worse → Product feedback thread (regression signal)
  • Nomad → Dashboard for trend tracking
  • Testimonial → Social proof capture pipeline
  • Not relevant → Logged only, no routing

Step 6 — Dashboard Logging: Every conversation gets a full structured record in Notion — regardless of classification. Nothing is discarded. Everything is queryable.

Special case: medication misspellings. When a customer misspells a medication name, the system routes to a dedicated safety alert channel. In healthcare software, medication errors are a patient safety issue — not a routine support ticket.

System 2: Prompt Agent

AI Ghost-Writer for Support Agents

When an agent types @Bot in an Intercom internal note, the Prompt Agent activates. But it doesn't just generate text — it decides what kind of response is needed.

Decision logic: If the agent says "tell the customer..." the AI drafts a reply posted as that agent. If the agent says "look up..." or "summarize..." the AI sends a private note back to the agent only.

Context loading: The system loads the full conversation history, the internal rules database, and the agent's real name. The AI knows the product, the policies, and who it's writing as.

Tool access: The AI agent has real tools at its disposal — Help Center Search, Help Center Scraper, Reply to Customer, and Send Note to Agent. It doesn't just generate text; it can look up real documentation and take real actions.

Guardrails are non-negotiable: Never hallucinate information. Never reveal it's AI. Never call clinicians "users." HTML formatting only. Contextual signatures that match the agent's style.

What the customer sees: A well-crafted, on-brand reply signed with their agent's name. Indistinguishable from a manually written response. The AI amplifies the agent — it doesn't replace them.

The AI ghost-writer pattern is transformative. It amplifies agents rather than replacing them. Adoption is dramatically higher than any "AI replaces the human" approach because agents stay in control of the relationship.

System 3: Smart Ticketing System

AI-Structured Engineering Escalations

When an agent tags a conversation with techsupport, the Smart Ticketing System takes over. What used to take 10–15 minutes of manual ticket creation now happens in under 30 seconds.

Three LLM passes, each with a specific job:

  1. Categorize — What type of engineering issue is this?
  2. Structure — Extract the relevant technical details into a standardized format
  3. Parse support notes — Pull agent observations and reproduction steps from internal notes

Automated outputs:

  • Creates a Notion ticket with full structured data (category, severity, reproduction steps, customer impact)
  • Posts a rich Slack announcement with direct links
  • Writes back: Slack thread linked to Notion ticket, Intercom admin note confirms creation
  • Round-robin assignment with route rules ensures fair workload distribution

The result: three-way cross-platform linking in under 30 seconds. Intercom conversation → Notion ticket → Slack thread. Every stakeholder can trace from any system to any other. Complete audit trail, zero manual linking.

System 4: Social Proof Capture

Automatic Testimonial Extraction & Routing

Customer praise is one of the most valuable signals a company receives — and one of the most commonly lost. This system ensures every testimonial is captured, structured, and surfaced.

Two triggers:

  • Automatic — The AI triage system (System 1) detects a testimonial classification
  • Manual — An agent adds a specific tag when they spot praise the AI missed

Processing pipeline: Fetches the full conversation, looks up the customer's medical specialty, and selects the right text source (AI-detected quote vs. agent-tagged message).

Output: Posts to the #social-proof channel as "LoveBot" with the verbatim quote, customer email, specialty, and a direct link to the conversation. Marketing, leadership, and the whole team see it instantly.

Outcomes

For Support Agents

Every conversation arrives pre-enriched with customer context. The AI ghost-writer eliminates repetitive drafting. Engineering escalations that took 10–15 minutes now take under 30 seconds. Agents spend their time on judgment and empathy — not data entry.

For the Product Team

Every conversation is classified and logged. Regression signals ("worse" classifications) surface automatically. Medication safety alerts route to a dedicated channel. Product decisions are backed by structured, queryable support data instead of anecdotes.

For Engineering

Escalation tickets arrive with AI-extracted context — category, severity, reproduction steps, customer impact. Three-way cross-linking (Intercom → Notion → Slack) means no context is lost. Fair round-robin assignment distributes workload evenly.

For the Company

Customer praise is automatically captured and surfaced. All support data is structured and queryable. Four Make scenarios run with zero manual intervention. The customer experience is unchanged — but the operational efficiency behind it is dramatically better.

Key Design Insights

  1. Two-layer classification: fast gate + detailed pass. The gating classifier handles 100% of volume for near-zero cost. Only messages needing deep analysis hit the expensive model. This saves AI cost while ensuring nothing is missed.
  2. The AI ghost-writer pattern is transformative. It amplifies agents rather than replacing them. Agents keep the relationship. The AI handles the writing. Adoption is dramatically higher than replacement approaches.
  3. Cross-platform linking creates a complete audit trail. Intercom → Notion → Slack. Any stakeholder can trace from any entry point to the full picture. No orphaned tickets, no lost context.
  4. A shared category registry enables system-wide consistency. The Notion-based registry is the single source of truth. Every system reads from it. When categories change, all systems update automatically.
  5. Graceful degradation over brittle perfection. If the AI classifier fails, the conversation still arrives in the queue — just unclassified. If the ticketing system errors, the agent can still create a ticket manually. Nothing breaks hard.

Builder's Note

Support agents don't want AI that replaces them. They want AI that removes the tedious parts — enrichment, triage, escalation formatting — and accelerates the skilled parts: drafting good replies, making judgment calls.

The Prompt Agent drafts a reply and posts it as the agent — maintaining the human relationship while eliminating writing time. This "AI-behind-the-human" pattern has higher adoption than any "AI-replaces-the-human" approach I've seen.

The four systems handle enrichment, triage, response drafting, escalation, and praise capture — the five biggest time sinks in a support operation. But they do it invisibly. The customer experience is unchanged. The agent experience is dramatically better.
